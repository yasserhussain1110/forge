# Day 157 · Week 23 · Quality evaluation

**Time:** about 3 hours (plus 30 minutes of coding practice)

## Why today matters
A fast engine that produces slightly wrong output is useless. Showing that your output quality matches the reference is what makes your speed numbers credible.

## Tasks
- [ ] Use lm-evaluation-harness's OpenAI-compatible API mode to evaluate Forge on GSM8K and part of MMLU through your server.
- [ ] Run the same evaluation against vLLM, and against Hugging Face `transformers` as the reference.
- [ ] Do it for 16-bit and for your quantized variants.
- [ ] Put the accuracy table in `RESULTS.md`. Investigate any gap larger than run-to-run noise.

## Done when
Forge's accuracy matches the reference within noise.
